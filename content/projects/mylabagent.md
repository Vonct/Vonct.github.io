# 项目背景

`myLabAgent` 是我围绕实验室日常研发与自动化场景持续搭建的一套共享 Agent runtime。目标不是只做一个能聊天的 demo，而是把检索、工具调用、记忆管理和垂直功能流程沉淀成一套可复用的运行时能力，服务 Web、CLI 以及后续扩展出来的新入口。

## 通用能力开发

- 支持 `Web` 与 `CLI` 双入口，共享同一套 Agent runtime
- 统一封装 `RAG` 检索、工具调用、本地 `skill` 挂载与 `sub-agent` 能力
- 用于承接文档检索、文件处理、命令执行等实验室常见任务
- 封装统一模型接入层，支持不同 LLM 的配置化切换与调用

![myLabAgent Web 端界面](./imgs/agent_web_weathewrquery.png)

Web 端更适合承接知识库、模型配置和可视化交互，保证检索、工具和会话能力在一个共享 runtime 上运行，而不是为界面单独复制一套逻辑。

![myLabAgent CLI / TUI 端界面](./imgs/agent_cli_interface.png)

CLI / TUI 端则更偏工程化工作流，适合围绕脚本、文档、代码库与本地命令执行展开连续任务。

## 垂直功能开发

围绕实验室实际需求，已经开始把共享 runtime 往垂直流程上推进：

- 从自然语言到 `DDS-IDL` 生成
- `TC4-PPU` 代码生成与集成

![myLabAgent CLI / TUI 使用 skills](./imgs/agent_cli_idlprompt.png)

通过 skill 与工具系统接入，保持调用方式、上下文管理和后续扩展的一致性。

## Agent 设计与工程化实现

### 共享运行时设计

Web 和 CLI 两个入口统一到同一套 Agent runtime，尽量避免一边修好了另一边又分叉。这样后续新增模型、工具、记忆层或垂直流程时，不需要重复维护两套实现。

### 会话与记忆机制

在当前实现里，`session`、`task` 和 `memory` 被拆成不同层次处理：

- `messages` 保存外层 transcript，只持久化 `user / assistant` 历史消息
- `tasks` 保存每轮执行轨迹，包括工具调用摘要与结果
- 当前单轮内的工具结果只在本轮 loop 里继续传递，不跨轮原样回放
- 轮次结束后把 prompt、answer、tool 摘要压缩成 `memory card`
- 下一轮根据当前 query 对 memory 做相关性打分，挑选高相关记忆注入上下文

### 自动化流程与通用能力沉淀

- 通用层统一处理模型调用、检索、权限、工具和会话
- 垂直层在此基础上封装成具体工作流，比如 IDL 生成、代码生成、集成检查
- 同一套能力可以从 Web、CLI 甚至未来的新入口复用，而不是每个场景都重新搭一遍

### 面向实际使用的打磨

除了功能本身，也持续在优化 CLI 交互体验、模型切换、输入反馈、事件流展示和记忆注入等细节。目标不是只让 Agent “能回答”，而是让整条使用路径足够顺手，适合在真实研发过程中长期使用。

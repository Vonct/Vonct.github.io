# 项目背景

`myLabAgent` 是我围绕实验室日常工作与开发提效持续搭建的一套共享 Agent runtime，底层基于 `Responses API`。我不想把它做成一个只能演示一次的 demo，而是希望它能在 Web、CLI 和后续垂直功能里长期复用。

## 通用能力开发

- 支持 `Web` 与 `CLI` 双入口
- 统一封装 `RAG` 检索、工具调用、会话持久化和本地 `skill` 按需加载能力
- 用于承接文档检索、文件处理、命令执行等实验室场景任务

![myLabAgent CLI / TUI 端界面](./imgs/agent_cli_idlprompt.png)

CLI 端则更强调效率和工程化工作流，适合直接围绕代码、文档和脚本执行做连续任务。

## 垂直功能开发

- `DDS-IDL` 生成
- `TC4-PPU` 代码生成与集成

这些垂直功能不是单独堆上去的脚本，而是复用同一套 runtime、工具和 session 能力承接的。这样做的好处是，通用能力和垂直能力可以共用同样的上下文管理、工具权限和对话链路。

## 我在这个项目里重点做的事情

### 共享运行时设计

我把 Web 和 CLI 两个入口统一到同一套 Agent runtime 里，尽量避免一边修好了另一边又分叉。这样后续加模型、加工具、加记忆层或者扩展垂直功能时，不需要重写两套逻辑。

### 会话与上下文管理

我把 session、task 和 memory 拆成不同层次处理：

- 当前单轮内的工具结果只在本轮 loop 中继续传递
- 跨轮不回放整段工具原文
- 轮末把关键内容压缩成 memory card，供后续按相关性注入

这样可以让上下文更干净，也让系统更适合长时间演进。

### 面向实际使用去打磨体验

除了功能本身，我也持续在优化 CLI 交互体验、模型切换、输入反馈、事件流展示这些细节。对我来说，真正能用的 agent 系统，不只是“能回答”，而是整个使用路径都足够顺手。

## 为什么它值得持续做

这个项目对我来说不是一个单点成果，而是一套可以不断承接新需求的基础设施。通用能力先打底，垂直功能再逐步接进去，后续无论是实验室工具、代码生成还是知识库问答，都可以继续沿着同一个 runtime 演进。
